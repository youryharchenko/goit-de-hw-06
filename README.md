## Підсумок

**Інфраструктура та генерація телеметрії (Producer)**

Налаштовано брокер Apache Kafka 4 (у KRaft-режимі без ZooKeeper) через Docker Compose.

Створено Python-скрипт (task1.py), який імітує роботу окремих IoT-датчиків: генерує унікальний незмінний sensor_id, випадкові показники температури (25–45°C) та вологості (15–85%) і надсилає їх у вхідний Kafka-топік (yukh_building_sensors).   

**Потокова обробка та агрегація (Spark Streaming & Windows)**

Розроблено PySpark-скрипт для зчитування потоку даних із Kafka.

Застосовано вотермарк (watermark — 10 секунд) для обробки запізнілих подій та Sliding Window (довжина вікна — 1 хвилина, інтервал зсуву — 30 секунд) для обчислення середніх значень температури й вологості в реальному часі.

**Інтеграція бізнес-правил із файлу (alerts_conditions.csv)**

Завантажено статичний конфігураційний файл із пороговими значеннями, кодами та текстовими описами алертів.

**Крос-об'єднання та виявлення аномалій (Cross Join & Filtering)**

Виконано операцію Cross Join між стрімінговими агрегованими даними та статичним довідником правил.Налаштовано інтелектуальну фільтрацію, яка визначає порушення лімітів з урахуванням неактивних меж (!= -999) та формує стандартизовані пакети сповіщень.

**Серіалізація та запис у вихідний Kafka-топік**

За допомогою функцій struct та to_json сформовано вихідні JSON-повідомлення (з полями window, t_avg, h_avg, code, message, timestamp).   

Налаштовано надійний запис активованих алертів назад у Kafka-топік (yukh_alerts_output) із підтримкою checkpointing.
